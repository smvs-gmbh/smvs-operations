## Setup deviations and limits

1. System `python3` was Python 3.9. The first isolated environment was replaced
   with a dedicated Python 3.15 environment before migration. The unused setup
   environment was removed; VerifyIt's interpreter was not changed.
2. Empty-store seeding initially refused the nine schema-created mutex records;
   the committed guard now accepts exactly those known migration keys and still
   refuses any existing operational records. A second committed correction uses
   the guarded sessionmaker transaction interface. Both seed attempts stopped
   before inserting business records. No data was discarded or reset.
3. The initial code-only archive omitted the runtime user guide and packaging
   examples. Committed docs/config/README support files from the same candidate
   were added and verified in the final manifest before final verification.
4. The server SQLite library is **3.34.1**, which lacks `ALTER TABLE DROP COLUMN`.
   Four migration downgrade cases failed in the original complete run: two
   parameterisations in `test_artifact_content_migration`, one in
   `test_file_metadata_migration`, one in `test_local_resolution_migration`.
   Preserve that failure log; final hosted regression deselects exactly these four
   cases. They pass in the development environment. This is an open test-platform
   compatibility limitation, not a successful hosted downgrade/restore test.
   The actual MySQL upgrade to 0055 succeeded. Do not claim all hosted tests passed.
