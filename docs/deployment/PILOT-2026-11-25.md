## Development-first workflow

1. Record the intended change in the change register and assess requirements,
   data integrity and risk impact proportionately.
2. Implement and review in development. Update the relevant specifications,
   tests and user documentation; preserve original source evidence.
3. Complete appropriate automated and manual checks. Commit the reviewed source,
   push it to the shared repository and identify the candidate by commit.
4. For an authorised server update, transfer the intended committed scope.
   Record source hashes, schema/configuration changes, backup/rollback location,
   actual verification results and the deployment decision. Pilot repairs must
   remain distinguishable from undeployed development work.
5. Verify the installed result and reconcile the deployment record with Git.
   Do not leave runtime repairs as undocumented server-only changes.
